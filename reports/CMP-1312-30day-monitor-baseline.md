**남은 가능성 3가지 — Meta 실집행 수치 없이는 가를 수 없다**

| # | 가설 | 판별 근거 |
|---|---|---|
| A | 광고가 ACTIVE 표시만 되고 실제 노출/과금이 안 되고 있다 | spend·impressions = 0 |
| B | 노출은 되는데 클릭이 0 (소재·타겟 문제) | impressions > 0, link clicks = 0 |
| C | 클릭은 있는데 랜딩에 도달하지 못한다 (URL·리다이렉트 결함) | link clicks > 0, LPV = 0 |

C 라면 예산이 그대로 새고 있다는 뜻이므로 가장 급하다.

**차단 요인**: 이 런에 Meta 광고 API 접근 수단이 없다. `/api/agents/me/secrets` = 빈 배열,

## 5. 라이브 접속 QA 계약 (재발 방지)

`PRODUCT.md` 에 계약으로 못박는다. 요지:

**라이브 오리진(`spacebogam.kr`)에 접속하는 모든 에이전트 브라우저 세션은, 스크립트가 저장소 안에 있든
런 스크래치에 있든, 유입 URL 에 `is_test=1` 을 붙인다.** 광고 원본 URL 을 그대로 붙여넣는 것은 계약 위반이다.

`check-qa-entry-urls.mjs` 는 `scripts/qa/**` 만 검사하므로 **런 스크래치 스크립트는 검사기가 못 잡는다** —
이 구간은 계약 준수로만 막힌다.

```sql
SELECT count(*) AS events, count(DISTINCT session_id) AS sessions
FROM spacebogam_funnel_events
WHERE page_path LIKE '/commercial/call%'
  AND NOT is_test
  AND occurred_at < '2026-08-23T11:00:00Z';   -- KST 20:00 = 오염 확정 구간 상한

-- 2) 표식 적용 (쓰기 — 승인 후)
UPDATE spacebogam_funnel_events
SET is_test = true, updated_at = now()
WHERE page_path LIKE '/commercial/call%'
  AND NOT is_test
  AND occurred_at < '2026-08-23T11:00:00Z';

-- 3) read-back
SELECT is_test, count(*) FROM spacebogam_funnel_events
WHERE page_path LIKE '/commercial/call%' GROUP BY 1;
```

상한을 2026-08-23T11:00:00Z(KST 20:00)로 잡은 근거: 마지막 QA 버스트가 19:02 KST 이고,
그 이후 이 경로에 기록된 이벤트가 없다. 상한 이후 유입은 실트래픽 후보로 남긴다.

## 7. 기준선 확정 사항

**§1 의 Day-0 수치는 확정하지 않는다.** 실트래픽이 0이므로 Day-0 자체가 아직 시작되지 않았다.

30일 테스트의 Day-0 은 **R3 가 해소되어 `/commercial/call/` 에 사람 방문이 확인되는 날**로 다시 잡는다.
구캠페인 수치(§1-4)는 비교용 고정 기준선으로 유효하다. 구캠·신규 수치는 혼합 집계하지 않는다.
